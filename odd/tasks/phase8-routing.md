# Phase 8A: intelligent routing

Phase 8's first delivery, `PLAN.md` §8A. The contract is settled and committed at
`ea629df`: ADR 0030 (decisions, the standard's wire, the gate, modes, escalation),
ADR 0031 (scoped catalogs and `shared`), ADR 0055 and ADR 0056 (the tool
contracts, which belong to 8B). Nothing here generates text or runs a tool.

Two units, in order, because 8A.2's `shared` catalog resolves names that 8A.1's
scope catalog defines, and both rewrite the same loader, validator, and schema.

## Specs

- S1 — `PLAN.md` 8A.1: a bot with a `system_one` routes an unmatched message
  through a System One endpoint and the confidence threshold; an answer at 0.9
  takes the transition and at 0.4 does not; a provider error falls back to
  triggers; `routing` under `llms` fails validation; the interim `Classify` port
  is gone.
- S2 — `PLAN.md` 8A.2: a scope entry wins over `shared`; `always` decides before
  a matching trigger; below the threshold with no default edge and no `fallback`
  node the graph enters `escalate` and the chat is held for a human; one log line
  carries node, question, answer, and confidence; pointing `base_url`, `model`,
  and the key at a second endpoint needs no code change.
- S3 — ADR 0030/0031 rules that outlive both units and are checkable: routing is
  decision-only (`LLMProvider.Classify` deleted, no `routing` under `llms`); the
  gate reads the answer's own `confidence`, never the largest probability; a
  scope reference resolves in the scope and then in `shared`, and a reference
  that resolves nowhere fails validation; a decision call carries at most 64
  questions and a `choice` at most 255 options; a provider that is absent, slow,
  or failing degrades to triggers and the default edge; a bot with no model runs
  deterministically.
- S4 — AGENTS.md: no new dependency, every deliverable checked in `PLAN.md` in
  the commit that completes it, the topic's owning document updated rather than
  duplicated, `config.schema.json` regenerated by `make schema`.

## Tasks

- T1 — S1: `spec.SystemOne` and the scope catalog, `botflota.SystemOneProvider`
  and its request/answer types, the `systemone` HTTP adapter over the standard's
  wire, the threshold gate in the engine, `Classify` deleted from the LLM port
  and from its implementations, and config validation for both changes.
- T2 — S2: the instance `shared` catalog and scope-first resolution, `routing`
  modes (`off`, `fallback`, `always`) and the graph override, `escalate` and the
  human hold, the per-message decision log line, and a second endpoint proven by
  configuration alone.
